# 人式读文档方案 —— Vision RAG 解答企业年报问答

> 本方案用于 Enterprise RAG Challenge 类任务：**多份上市公司年报 PDF → 逐题问答**。
> 核心主张：**让 AI 像人一样读文档**，而不是写程序去"检索+流水线答题"。

---

## 一、核心原则：你就是那个读文档的人

**不写批量脚本、不跑流水线、不写 agentic 循环。** 你是专业文档阅读者，手里有一套工具，
一次认真做一题：

```
查目录 → 视觉看页 → 没找到就深挖（换词/翻邻页）→ 收敛（给答案+页码，穷尽才答 N/A）
```

- 每一步（看哪页、看什么、要不要深挖）由你当下判断，没有预定义流程
- 工具只提供能力；判断力来自你
- 一次一题，每题务必给出答案（含 N/A），不敷衍

### 为什么放弃"程序化流水线"
旧方案（本仓库已移除）用 `ingest → ask` 批量管道：TF-IDF 粗筛 → 视觉精排 → 深读答题。
问题在于：把"读哪一页、信哪一段"的判断交给了固定代码，遇到年报里的
乱码页、跨页表格、同义词差异、陷阱题就系统性失效；
每换一类题就要改代码，成本高、上限低。

## 二、工具集（`scripts/agentic_tools.py`，你自主调用）

| 工具 | 用途 | 什么时候用 |
|---|---|---|
| `scan_index(pdf, keywords)` | **查目录**：关键词出现在哪些页 + 上下文 | 第 1 步，定位大概位置 |
| `read_vision(pdf, page0, instr)` | **看图（你的眼睛）**：渲染该页，按你的指令提取 | 第 2 步，视觉查看；**乱码页/表格页必用** |
| `read_text(pdf, page0)` | 快速瞄一眼文本层（零成本） | 先看文字，再决定要不要看图 |
| `search_pages(pdf, query)` | 辅助检索（带词干匹配） | 目录扫不到时兜底 |
| `verify_quote(quote, evidence, kind, value)` | 自检：引用真实存在于页面 | 出答案前核验 |

`read_vision` 内部经 `ds_client.py` 渲染并调用 DeepSeek 视觉模型（`deepseek-v4-flash-vision-exp`）。

环境：`pip install openai pymupdf`；API key 用环境变量 `DEEPSEEK_API_KEY` 或 `~/.deepseek_api_key`。

## 三、工作流（像人一样读文档）

1. **查目录（`scan_index`）** —— 主动换同义词扫。
   例：题目问 "employees let go"，年报可能写 "headcount reduction / job cuts / restructuring"；
   不要只搜题面原词。
2. **视觉看页（`read_vision`）** —— 翻开那一页，按你构造的指令逐字读出数字、表格、图注。
   文本层先用 `read_text` 瞄一眼；**乱码页、表格页、图表页直接用 `read_vision`**。
3. **深度查看** —— 没找到就换关键词再扫、翻 ±1 邻页、找动词（appointed/resigned/effective）。
4. **收敛** —— 找到就给答案 + 物理页码；穷尽目录与邻页仍无，明确说明查过哪里，再答 N/A。

## 四、判定规则（三轮验证沉淀，务必遵守）

### 4.1 boolean：必须有"变化证据"
> **词出现 ≠ 事件发生。** 判定标尺：必须有**变化**的证据。

| 判 True | 判 False |
|---|---|
| 与去年对比的数字变化（DPS 提高、目标上调） | 仅有政策/意图描述（"分红政策为长期意图≥40%"） |
| 报告期内**实际完成**的事件（并购完成、回购执行、新设基金、产品发布） | 提案／提议／计划（"proposed"、"intends to"） |
| 明确授权并执行的计划（董事会授权回购且已回购） | 历史授权（如 2018 年股东大会授权，本年无动作） |
| 新增披露／新设机构／新目标 | 例行合规声明、风险因素措辞、集成第三方能力 |

拿不准 → **按 False**（round2/3/4/5 官方真值中 False 更多）。

### 4.2 number：单位与年份列
- **核对 2022/2021 列序**：这是本项目犯过的最贵错误（round3 Q9 把 2021 年的借款
  1,481.6 当成 2022 年，真值 1,361.7）。表格首列未必是当年，**用期初/期末、MD&A 表述交叉验证**。
- **题面单位写死并与报告一致**（"in millions of CAD" / "in thousands of USD" / "in AUD"），
  千元↔原始值换算后作答（round4 Q1 被测方把千元数当 USD，失分）。
- 注意**财年截止日**（Empire 5/7、Incitec 9/30、Structural 6/30 等）与**报告货币**
  （Incitec FS 为 AUD，分部数据却用 US$m）。
- 五年摘要的取整值（如 Playtech 1,602）与利润表精确值（1,601.8）在 1% 容差内都算对。

### 4.3 N/A 纪律（最易错，连续两轮被测方栽在这里）
> **数据未披露 → N/A；只有报告明确写出该指标且数值为 0 时 → 答 0；禁止自算。**

- 利润表**有** "$—" 营收行（如 Terns 的 License revenue $—）→ 答 **0**
- 利润表**无** 该行（Ocugen 从 Operating expenses 开头、Armadale 从 Admin expenses 开头、
  Atreca/NuCana/Westwater 同理）→ 答 **N/A**
- 报告未披露的指标（如毛利率；round2 官方对**有营收有 COGS 的 Ritchie** 也答 N/A）→ **N/A**
- 不可自行用 (收入−成本)/收入 计算后填数
- **陷阱**：预营收生物科技也可能有营收行（INMUNE 2022 REVENUE $374 千）——必须实读利润表，
  不能凭"预营收"想当然

### 4.4 name / names（职位与公司名）
- **键/答案一律用报告原词**：`Director` ≠ `Non-Executive Director`
  （round4 Q30 我键写 Director，报告原词是 Non-Executive Director）
- 多值职位用 **names kind**（Jaccard 部分分，官方惯例）；单值才用 name（精确匹配）
- 建键前**穷举**报告中所有 `commenced / retired / resigned / appointed / designate` 记录：
  分拆或董事会改组的公司变动条目极多（Incitec 有 CFO、President、Chairman/CEO/CFO-designate；
  Structural 有 Chairman 辞任 + 3 名 NED 任命），单值/双值键必漏项
- **排除报告日后事项**（"Subsequent to the reporting date"、次年年初生效的任命不算期内变动）
- names 比较题：公司名字符串必须与题面一致（Jaccard 按逗号切词，简写会得 0）；
  比较口径统一用**集团**数据，不要用母公司口径（round4 Q32 被测方用母公司 22 人，真值集团 819）

### 4.5 反模式（不要做）
- ❌ 写批量脚本遍历所有题 —— 一题一题读，质量更高
- ❌ 信元数据 flag —— `subset.json` 的 `has_*` 标记会错（Medallion 标 buy=0 但报告确有回购）
- ❌ 只读文本层 —— 乱码/表格/图表页必须 `read_vision`
- ❌ 推断/自算未披露数据 —— 见 4.3

## 五、方案验证：round2 官方数据集 + 三轮交叉验证

### 5.1 官方 round2 数据集（100 题，最硬核验证）

另一 AI 用人式读文档方案重做官方 round2 全部 100 题（官方出题、官方答案键，无人为设计）：

| 指标 | 结果 |
|---|---|
| 最终得分（官方严格口径） | **143.0/155 = 92.26%**（官方榜首 78.8%） |
| 宽松口径（格式/单位/口径差异放行） | 155/155 = 100% |
| 分题型 | boolean 42/48 · name 17/17 · names 15/15 · number 69/75 |
| 评分进程 | 54.55% → 68.39% → 71.61% → **92.26%** |

额外教训（本轮独有）：① 题面必须**逐字匹配官方**（23 条错配损失约 34 分）；
② 官方 boolean 口径 = "年报是否提及"（提及即 True），比 4.1 的严格校准更宽；
③ 官方 names GT 用**逗号**分隔，分号会 Jaccard=0；④ number 注意原始值/期末/单期口径。
详见 `05_结果/round2官方数据集验证.md`。

### 5.2 自制仿考三轮（round3/4/5，各 33 题）

用本方案驱动的被测 AI，独立完成三轮各 33 题（题集与 round2 官方题零重复，答案均经原文核实）：

| 轮次 | 机械得分 | boolean | number | name/names | 主要失分 |
|---|---|---|---|---|---|
| round3 | 43.0/62 = **69.35%** | 8/10 | 89.3% | 25%/33% | 字符串简写、1 处校准误判 |
| round4 | 47.0/62 = **75.81%** | **10/10** | 75.0% | 25%/67% | N/A 纪律、多值漏答、单位换算 |
| round5 | 54.0/63 = **85.71%** | **10/10** | 89.7% | 57%(Jaccard) | N/A 纪律（3 题） |

**结论**：方法可复刻且稳定进步。稳定项 = 取数、单位、boolean 校准、员工比较；
唯一系统性弱点 = "未披露数据"的判定口径（连续两轮答 0 而非 N/A）——
把 4.3 规则在提示里前置即可消除。

各轮的完整裁定见 `03_测试集/roundN/roundN_交叉检查报告.md`。
其中也如实记录了**我方答案键自身的错误**（round3 键错 4 处、round4 键错 1 处、
round5 键不完整 2 处）——正确答案键同样必须逐条回原文核实。

## 六、复现步骤

```bash
# 1) 用 skill 逐题作答（人式流程，非脚本）
#    题集与模板：03_测试集/roundN/roundN_questions.json + roundN_submission_template.json

# 2) 评分（官方口径，任意轮次）
cd 04_评分
python grade.py --questions ../03_测试集/round5/round5_questions.json \
                --key       ../03_测试集/round5/round5_answers_key.json \
                --submission <你的提交.json> --show-wrong
```

语料：`02_语料/subset.json` 给出 100 家公司 → PDF sha1 → 币种与元数据标记；
其中 61 份已建视觉索引（清单见 `02_语料/已建视觉索引的61家公司.txt`）。
PDF 本体体积大，不随发布包分发；按 sha1 从原数据集 `round2/pdfs/<sha1>.pdf` 取用即可。

> **协作提示**：把题集与模板交给被测方即可，**答案键留在共享目录外**
> （round5 时答案键被被测方删除过一次）。
